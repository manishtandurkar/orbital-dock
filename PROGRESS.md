# Progress log (context for future Claude sessions)

This file records what has been built so far and what is left. Keep it updated at the end of each work session. `CLAUDE.md` imports it, so a new Claude Code session loads it automatically.

## Plan

Six milestones, each committed and pushed on branch `claude/magical-cannon-9rcwph`:

1. Engine skeleton (CMake, window, input, timer, state machine, shader, mesh, camera)
2. Models and lighting (Assimp OBJ loading, textures, Blinn-Phong with sun + point lights, skybox, scene graph)
3. Flight, debris, collision (pod thrusters, debris field, sphere/AABB collision, chase camera with shake)
4. Station and docking (rotating station hierarchy, articulating arm, docking tolerance check with hold timer, reparent on dock)
5. EVA and mission flow (first-person hull walk, hold-E repair, life-support timer, win/lose)
6. HUD, audio, polish (ImGui menus and HUD, miniaudio sound events, README)

## Decisions made

- Placeholder 3D models are generated by a throwaway script (not committed) and saved as OBJ + MTL in `assets/models`. The user will open and replace them in Blender later. Keep the same file names so no code changes are needed.
- No CI. Only Linux (Xvfb + Mesa) builds were verified by Claude; macOS and Windows must be checked by the team.
- Third-party code: GLAD (GL 3.3 core, generated with glad 0.1.36, `--no-loader`, loaded via `glfwGetProcAddress`), stb_image and miniaudio 0.11.21 are vendored in `third_party/` with tiny `.c` implementation units. GLFW 3.4, GLM 1.0.1, Assimp 5.4.3 (OBJ importer only) and Dear ImGui 1.91.5 come from `FetchContent`.
- `src/platform/ExecutablePath.cpp` is the only file with OS-specific code. `core/Assets` resolves `assets/...` next to the executable (falls back to the working directory).
- Private members use a trailing underscore (`window_`).
